# 产品形态修正案(Steven 定调,2026-07-26)

> 地位: Master Roadmap 与 OS 3.9+ Blueprint 的上位修正;OS 3.9 W4 起生效
> 一句话: **用户面收缩到"三键",系统面模板化**——漏斗与 Webinar 由 super admin 统一控制,普通用户永不生成它们

## 一、用户是谁(修正认知)

- **系统用户 = 全部由招募路径进来的事业伙伴**。零售产品使用者永远不接触本系统
- 即使产品使用者对事业产生兴趣,也必须走完整招募流程(看录制 webinar → 异议处理 → 成交加入)后才成为系统用户
- 由此:入门访谈的 A/B 分叉仍然有效(产品先行 vs 事业先行),但**两类人都是"已加入的伙伴"**——访谈问的是她的故事从哪开始,不是她要不要加入

## 二、标准招募流水线(系统要服务的主链路,Steven 原述)

```
招募广告 → 兴趣点击 → 漏斗留名单 → WhatsApp 首触引导看【录制好的 Webinar】
  → 未行动: WhatsApp 跟进 + Email 跟进
  → 看完: 异议跟进 → 成交加入
  → 加入后: 自用产品(首周带法) → 开始使用 NextShift OS 做招募+零售
```

## 三、用户面:小白只做三件事(+看懂数字)

1. **发**: 发 AI 生成的文案+视频(含配图指引 G7)
2. **投**: 打广告(小额、有引导、有止损线)
3. **跟**: WhatsApp/Email 跟进(用事业包话术模板,一键复制)
4. 广告与漏斗数据回流 → **AI 分析并用人话告诉她下一步**("这周 30 人点了广告,5 人留资料,2 人看完 webinar——今天跟进这 2 个人")

用户面**不存在**: 漏斗编辑器、webinar 生成、页面 Section 拖拽、任何"生成漏斗/讲座"按钮

## 四、系统面:super admin 模板化

- **漏斗**: 固定几套模板(零售版/招募版),super admin 创建与迭代;用户的漏斗 = 模板实例 + 个性化槽位自动填充(姓名/头像/个人故事/WhatsApp 号,全部来自 Brand DNA,零手工)
- **Webinar**: 录制好的视频,中央托管;用户漏斗指向它,但**归属追踪**必须把留名单/看完的线索路由回该用户的 WhatsApp
- **数据**: super admin 看全局(哪套模板转化好→迭代模板);用户看自己的简版数字(AI 解读)
- 既有的生成技术(G0-G5)不浪费: 转为 admin 造模板的工具 + 用户面的内容生成(发帖/视频/跟进话术仍是 AI 个性化)

## 五、既有工作的重定位

| 已建能力 | 新角色 |
|---|---|
| G1 内容引擎 | 不变——用户面核心("发") |
| G2 webinar/lead-magnet 生成 | 降为 admin 工具;用户面入口移除 |
| 漏斗编辑器(#145 标题编辑等) | 降为 admin 工具 |
| O2/O3 访谈+默认值 | 不变——个性化槽位的数据源 |
| M1 双轨隔离 | 不变——模板双轨的基础 |
| G4/G5 合规+可见性 | 不变——所有生成共用 |
| B 路径首周带法(事业包) | 加入后 Day4 闸门过后,系统**自动实例化**她的漏斗——"你的系统已经就绪"即里程碑时刻 |

## 六、细节拍板进度

1. **Webinar 托管(✅ 2026-07-26 定)**: 自己录制(工具随意)→ mp4 上传视频 CDN(首选 Bunny Stream,低流量约 RM5-20/月;备选 Vimeo Pro)→ 嵌入系统自有 webinar 页。**"看完"进度事件必须归系统所有**(播放器 progress 回传),它是招募流水线的换挡信号(未看→继续跟进/看完→异议处理)。禁用 Loom 作托管(归属链路外流)、禁用 VPS 自托管(带宽扛不住)。版本策略: v1 全团队共用一个版本
2. **个性化槽位(✅ 2026-07-26 定)**: 用户五槽=姓名/头像/个人故事/WhatsApp/Email(全部来自 Brand DNA,零手工);系统自动两槽=归属追踪码(埋全链接)、语言(zh/en/ms,访谈选择题定);进化一槽=见证素材(初期用团队见证,她的 Day30 对比照/打卡攒够后系统提示替换为本人故事——漏斗随旅程升级,接事业包"before 照=活招牌")
3. **广告模式(✅ 2026-07-26 定)**: 阿姨**自己动手** FB boost——系统手把手给步骤(截图级引导)、预算线 RM20-50/天 ×7 天、明确止损规则(亏到线喊停)。设计哲学(Steven 原话):"她始终有一天也是要自己独立的,只是逐步开始带着她走而已"——系统是陪驾教练,不是代驾;能力逐步移交,依赖逐步撤除。广告数据回流走既定路径(截图/数据→AI 分析→人话建议,呼应 Roadmap C0)

**三项全部拍板,修正案定稿(2026-07-26)。交 Sonnet 排 W4:模板化+归属追踪+webinar 页(Bunny Stream)+广告陪驾。**

## 七、漏斗族群版本(✅ 2026-07-26 定)

架构: **一个母版 × 族群文案层**——结构(Hero/痛点/原理/见证/表单/FAQ/CTA)全族群共用;族群层只替换痛点清单、开头钩子、见证人选、语气。族群是模板的一个维度,与语言(zh/en/ms)、轨道(retail/recruitment)平行,同属 T2 槽位体系。

族群全集(9): 上班族 / 全职妈妈 / 蓝领·轮班族 / Gen Z / 大学生 / 老板 / 乐龄·退休 / 新加坡马劳 / 单亲爸妈(文案需格外温柔+合规加严)

**首发三族群(Steven 定)**: 上班族、全职妈妈、蓝领/轮班族。投广告验证转化后再扩。
- 痛点素材来源规矩: 每族群的痛点清单必须源自 Steven 实际招募过的真人故事(待口述,每族群一个成功案例),禁止 AI 凭空拟痛点

## 七、阿姨接受度判定(Fable 评估)

会接受,当且仅当守住四条:
- 她的首页永远只有一件事(已达成,批 4)

- 数字永远带着"所以你今天做什么"的翻译,不裸奔
