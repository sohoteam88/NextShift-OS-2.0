# System Context

Version: 1.0

Status: Approved

## Purpose

This document provides the global system context for AI contributors working on NextShift OS.

It defines the architectural mindset, repository navigation order, decision hierarchy, and contribution rules that every AI system must understand before generating code, documentation, or architecture proposals.

This document is the primary onboarding guide for AI contributors.

## Mission

The mission of this document is to ensure that every AI contributor shares the same understanding of NextShift before performing any work.

AI should understand the system before modifying the system.

## What is NextShift?

NextShift is an AI Guided Business Operating System.

It is not:

- An AI Writer
- A CRM
- A Funnel Builder
- A Marketing Automation Platform
- A Chatbot

Those are execution capabilities.

NextShift exists to help entrepreneurs:

- Understand better.
- Decide better.
- Execute faster.
- Learn continuously.
- Build better businesses.

## Architectural Identity

NextShift is a Cognitive Architecture.

The platform is organized around intelligence rather than software features.

Business understanding is the center of the architecture.

Everything else exists to support that understanding.

## Repository Reading Order

Every AI contributor should read the repository in the following order.

### Step 1 - Governance

Understand how the repository evolves.

### Step 2 - Foundation

Understand how NextShift understands businesses.

### Step 3 - Constitution

Understand permanent product principles.

### Step 4 - Reference Architecture

Understand the complete system.

### Step 5 - Architecture

Understand system responsibilities.

### Step 6 - Contracts

Understand implementation obligations.

### Step 7 - Specifications

Understand implementation details.

### Step 8 - Source Code

Only after understanding everything above.

## Architecture Hierarchy

```text
Governance
  -> Foundation
  -> Constitution
  -> Reference
  -> Architecture
  -> Contracts
  -> Specifications
  -> Interfaces
  -> Implementation
  -> Source Code
```

Higher layers always override lower layers.

## Core Intelligence Loop

Everything inside NextShift exists to strengthen this loop.

```text
Observe
  -> Understand
  -> Reason
  -> Recommend
  -> Discuss
  -> Decide
  -> Execute
  -> Measure
  -> Reflect
  -> Learn
  -> Improve
```

If a proposal bypasses this loop, it requires architectural justification.

## Core Components

The platform is organized around four cognitive systems.

```text
Business Brain
  -> Decision Brain
  -> Execution Layer
  -> Learning System
```

These systems are permanent architectural concepts.

## Business Twin Principle

The Business Twin is the single source of business understanding.

No component should create an independent business truth.

Every intelligent component should consume Business Twin context.

## AI Responsibilities

AI contributors should:

- Preserve architecture.
- Improve implementation.
- Reduce complexity.
- Strengthen the Business Twin.
- Improve business intelligence.
- Explain reasoning.

AI should not redefine the architecture without an approved RFC.

## Modification Rules

Before making any significant change, AI should ask:

1. Does this align with the First Principles?
2. Does this strengthen the Business Twin?
3. Does this preserve the Cognitive Architecture?
4. Does this improve decision quality?
5. Does this improve long-term maintainability?
6. Does this require an RFC?

If the answer to Question 6 is yes, implementation should pause until the RFC process is completed.

## Source of Truth

When conflicts occur, resolve them using this priority:

1. Governance
2. Foundation
3. Constitution
4. Reference Architecture
5. Architecture
6. Contracts
7. Specifications
8. Interfaces
9. Source Code

Code is never the highest authority.

## AI Contribution Workflow

```text
Read
  -> Understand
  -> Analyze
  -> Propose
  -> Review
  -> Implement
  -> Audit
  -> Learn
```

Implementation should never begin without understanding.

## Success Criteria

An AI contribution is successful when it:

- Preserves architectural consistency.
- Improves business intelligence.
- Produces maintainable implementation.
- Aligns with repository governance.
- Strengthens the Business Twin.
- Supports the Cognitive Architecture.

## Guiding Principle

Every contribution should leave NextShift more coherent, more intelligent, and easier to evolve than before.

Understanding always precedes implementation.
