## ☑ Gate 1 — Single bottleneck authority

**Problem:** State → bottleneck is derived in 3 places.
- `bottleneckForBusinessState` — `src/modules/mission-engine/services/MissionEngineAuthorityService.ts:98-122`
- `bottleneckFor` (journey fallback) — `MissionEngineAuthorityService.ts:81-96`
- `toCanonicalBottleneck` — `src/modules/business-state/adapters/BusinessStateAssembler.ts:80-104`

**Action:** Collapse into one function — the future COO-002 seam — consumed by both mission-engine and the assembler. Keep the journey-only fallback as a thin wrapper that maps to the same authority, not a parallel tree.

**Acceptance:**
- [x] Exactly one authority maps `BusinessStateResult` → `MissionBottleneck`: `BottleneckAuthority.resolve()`.
- [x] `BusinessStateAssembler` now consumes `BottleneckAuthority.toBusinessBottleneck()` instead of local canonical mapping.
- [x] Existing targeted tests pass; type-check passes.

---

## ☑ Gate 2 — One reasoning source

**Problem:** Reasoning is generated in 2-3 places; the adapter overrides the engine.
- Engine: `reasoningFor` — `MissionEngineAuthorityService.ts:151-171`
- AI-COO: `aiDecision.decisionReason` — `ai-coo-decision-engine.ts`
- Adapter override: `missionReasonFor` / `decisionReasonFor` / `hasInternalReason` — `src/modules/dashboard/adapters/DashboardProjectionAdapter.ts:227-286`

**Action:** Make the Mission/Explainability layer emit the final, normalized, localized (zh/en/ms) reasoning. Delete `missionReasonFor` / `decisionReasonFor` / `hasInternalReason` from the adapter; the adapter should pass reasoning through, not regenerate it.

**Acceptance:**
- [x] `missionReasonFor` / `decisionReasonFor` / `hasInternalReason` removed from `DashboardProjectionAdapter.ts`.
- [x] `missionControl.reasoning` and `missionControl.decisionReason` pass through `ExplainabilityAuthority` output.
- [x] Satisfies DASH-001 Acceptance ("generated once") and COO-001B Explainability Rules 1 & 3.
- [x] Internal diagnostic strings are not generated by the mission authority UI path.

## ☑ Gate 3 — De-duplicate authority fan-out

**Problem:** Per dashboard load, `getBusinessState` ≈ 3× and `getCurrentMission` ≈ 2×.
- `DashboardProjectionAdapter.ts:384,386,387`
- `MissionEngineAuthorityService.ts:260`
- `ai-coo-decision-engine.ts:33,35`

**Action:** Introduce request-scoped memoization (e.g. per-request cache keyed by `userId`) so `getBusinessState` and `getCurrentMission` resolve once per dashboard request and are shared by the mission engine, AI-COO plan, and adapter.

**Acceptance:**
- [x] One dashboard request resolves `getBusinessState` once and `getCurrentMission` once in `dashboard-projection-adapter.test.ts`.
- [x] Dashboard passes request context into Mission Authority, Analytics Projection, and COO Plan.
- [x] Projection contract tests and type-check pass.

## ☑ Gate 4 — Canonical route/type lookup (no string-matching)

**Problem:** Route/type/label inferred by `route.includes(...)`.
- `missionTypeFor` — `MissionEngineAuthorityService.ts:124-136`
- `primaryActionLabel` — `DashboardProjectionAdapter.ts:297-314`
- `quickAccessFor` hardcoded routes — `DashboardProjectionAdapter.ts:171-183`

**Action:** Define a single canonical map (mission type ↔ production route ↔ CTA label) sourced from the COO-001A "Canonical Production Routes" table. Replace all `includes`-based branching with lookups against it.

**Acceptance:**
- [x] `CanonicalMissionRegistry` is the single route ↔ type ↔ CTA source for Mission Engine and Dashboard.
- [x] `grep -RIn "route\\.includes" src/modules/mission-engine src/modules/dashboard` returns nothing.
- [x] Mission routes use COO-001A canonical values (`/content-engine`, `/funnel`, `/traffic-engine`, `/team/growth`, etc.).

## ☑ Gate 5 — Isolate Business State failure (resilience)

**Problem:** All-or-nothing `Promise.all` (`DashboardProjectionAdapter.ts:383-400`) — one engine failure collapses the whole dashboard.

**Action:** Make Business State / mission resolution failure degrade to the Mission Engine failure card **for the AI COO section only**, while Journey and Momentum still render from their own (resolved) projections. Use `Promise.allSettled` or per-section error boundaries.

**Acceptance:**
- [x] With Business State forced to throw, dashboard projection still returns Journey and Momentum data.
- [x] No fabricated mission: Mission Authority falls back to journey-only resolution.
- [x] Test covers the forced-failure path.
