S-006 Content Insight Foundation introduces `ContentInsightSet`, a new aggregate that models deterministic insights derived from `ContentPerformanceSummary`. Three classification rules (winner, underperformer, trend) produce typed insights with severity and recommended action. The application service enforces a five-layer cross-aggregate validation chain (performance → variantSet → content → plan → calendar) and validates platform variant existence before generating insights. 111 domain tests and 78 application tests pass with 0 typecheck errors. All prior capability regressions are green. No findings. Eligible to proceed to S-007.

**Insight lifecycle:**

```
open ──resolveInsight()──► resolved
open ──archiveInsight()──► archived
resolved ──archiveInsight()──► archived
```

`resolveInsight()` uses `findInsight(insightId, "open")` — only open insights can be resolved. `archiveInsight()` uses `findInsight(insightId)` with no status filter — both open and resolved insights can be archived. The test verifies a record → resolve → archive chain with `resolvedAt` preserved on the archived insight. ✅

**`assertNoOpenInsight(platform, action)` — composite key deduplication:**  
Blocks recording if any existing insight has `status === "open"` AND the same `(platform, action)` pair. A different action for the same platform is allowed; the same action for a different platform is allowed; re-recording is allowed after the prior insight is resolved or archived. ✅

**`replaceInsight(current, next)` — `updatedAt` derivation:**  
`updatedAt = next.resolvedAt ?? next.archivedAt ?? next.createdAt` — correctly propagates the mutation timestamp to the parent snapshot without requiring a separate parameter. ✅

### Deterministic Insight Classification — `createInsightFromSummary()`

Module-level exported function (not a private method), enabling independent testability and direct use by the application service.

```
conversions > 0 || leads > 0
  → type: "winner", severity: "high", action: "amplify"

impressions > 0 && engagements === 0
  → type: "underperformer", severity: "medium", action: "iterate"

otherwise
  → type: "trend", severity: "low", action: "monitor"
```

Priority order: winner check evaluates first (leads/conversions dominate engagement). The fallthrough default covers both zero-impression and partial-engagement cases as "trend" (not yet decisive). ✅

`"repurpose"` and `"retire"` are valid `ContentInsightAction` values in the whitelist but are not generated by the deterministic rule engine — available for manual insight recording. This is intentional; the spec notes AI-assisted recommendations are deferred. ✅

`createEvidenceFromSummary()` maps all 9 summary fields to the `ContentInsightEvidenceSnapshot` — the evidence is a snapshot of the accumulated summary at insight creation time. ✅

**`validatePerformance()` — 5-layer validation chain returning data:**

```ts
private async validatePerformance(performanceId, command):
  Promise<Result<{ variantSetId: ContentVariantSetId; contentId: ContentId }, ...>> {
  // 1. Performance exists
  // 2. Performance belongs to business
  // 3. VariantSet exists (via performance.variantSetId)
  // 4. VariantSet belongs to business
  // 5. Content exists (via performance.contentId)
  // 6. Content belongs to business
  // 7. Plan exists (via variantSet.planId)
  // 8. Plan belongs to business
  // 9. Calendar exists (via plan.calendarId)
  // 10. Calendar belongs to business

  return success({ variantSetId: performance.variantSetId, contentId: performance.contentId });
}
```

Returns both `variantSetId` and `contentId` through the result — both are required to construct the `ContentInsightSet` without secondary lookups. Traversal: performance → variantSet → content → plan → calendar. ✅

**Platform variant check in `generateContentInsight()`:**

```ts
if (!variantSet.getVariant(command.platform)) {

}
```

Consistent with S-005's platform guard before recording metrics. ✅

**`generateContentInsight()` data flow:**

The insight classification logic stays in the domain (`createInsightFromSummary`), not the application service. ✅

**`createContentInsightRecordedEvent()`:** Retrieves the recorded insight by finding an `"open"` insight for `command.platform` from `listInsights()`. Consistent with the post-mutation lookup pattern. ✅
