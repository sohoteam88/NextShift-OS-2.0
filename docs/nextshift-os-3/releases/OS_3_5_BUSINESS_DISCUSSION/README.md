## Purpose

This release candidate package records the OS 3.5 delivery theme:

```text
Business Brain Starts Talking
```

OS 3.5 gives the user their first way to talk back to the Business Brain. A "Discuss with AI" entry point appears on the Today's Recommendation card, backed by a Business Discussion service anchored to the current recommendation and decision context, with all LLM traffic routed exclusively through the `modules/ai` router and gated by a per-tenant daily quota. In parallel, OS 3.5 closes the first full flag lifecycle loop: the four remaining runtime flags (Mission, Business State, CRM, Command Center) graduate to default ON, the Revenue and Analytics legacy fallback branches (promised since OS 3.3) are physically removed, and the flag registry gains a compile-time-enforced lifecycle field for future auditability.

This package prepares the release for approval. It does not create a tag, merge to `main`, deploy production, or approve release by itself.

## Release Capabilities

### Business Brain Starts Talking

When `NEXT_PUBLIC_ENABLE_AI_DISCUSSION=true`, the Today's Recommendation card exposes a "Discuss with AI" entry point. The discussion is anchored to the current recommendation and decision context — not an open-ended chat. Each session is capped at 5 turns, with turn-usage and quota state surfaced in the UI.

All discussion traffic routes exclusively through `modules/ai` router (`getRouterForTenant`), which enforces a per-tenant daily call quota (`AI_DAILY_CALL_LIMIT_PER_TENANT`, default 200) before any generation call is dispatched.

### Flag Lifecycle Closes Its First Loop

Four runtime flags graduate to default ON:

```text
NEXT_PUBLIC_ENABLE_RUNTIME_MISSION
NEXT_PUBLIC_ENABLE_RUNTIME_BUSINESS_STATE
NEXT_PUBLIC_ENABLE_RUNTIME_CRM
NEXT_PUBLIC_ENABLE_COMMAND_CENTER
```

Revenue and Analytics runtime adapters — graduated to default ON in OS 3.4 — have their legacy fallback branches physically removed. Only the runtime-construction-failure safety net remains (`isEnabled: () => true`); there is no more flag-controlled legacy-only code path for these two modules.

The runtime flag registry (`src/lib/runtime-flags.ts`) now records `lifecycleStatus: 'introduced' | 'graduated'` with a compile-time discriminated union (`graduated` requires `graduatedAt`; `introduced` forbids it), closing the audit trail for future flag graduations and removals.

### ESLint CLI Migration

`next lint` is replaced by ESLint CLI with a flat config (`eslint.config.mjs`) and an auto-generated module-boundary ruleset (`eslint-boundaries.config.mjs`, regenerated by `scripts/generate-eslint-boundaries.ts`, checked in CI via `--check`). The authoritative lint baseline is **409 boundary warnings + 4 hooks warnings, 0 errors** — the previously reported 192/413 counts were artifacts of the old `next lint` tool's reduced coverage, not real drift.
