## Overall Result

**PASS**

S-007 Content Recommendation Foundation introduces `ContentRecommendationSet`, a new aggregate that derives actionable recommendations from open `ContentInsightSnapshot` records. `createRecommendationFromInsight()` maps insight action to priority and composes a rationale string deterministically. The application service enforces a six-layer cross-aggregate validation chain (insightSet → performance → variantSet → content → plan → calendar), requires the source insight to be `"open"` before generating a recommendation, and publishes 7 distinct event types. 118 domain tests and 83 application tests pass with 0 typecheck errors. All prior capability regressions are green. No findings. Eligible to proceed to S-008.

**Recommendation lifecycle:**

```
open ──applyRecommendation()──► applied
open ──dismissRecommendation()──► dismissed
open ──archiveRecommendation()──► archived
applied ──archiveRecommendation()──► archived
dismissed ──archiveRecommendation()──► archived
```

`applyRecommendation()` and `dismissRecommendation()` use `findRecommendation(id, "open")` — restricted to open only. `archiveRecommendation()` uses `findRecommendation(id)` with no status filter — applicable to any status. This mirrors S-006's resolve/archive pattern extended with a second terminal state (`"dismissed"` alongside `"applied"`). ✅

**`assertNoOpenRecommendation(insightId, action)` — composite key:**  
Guards on `(insightId, action)` pair with `status === "open"`. Once a recommendation is applied, dismissed, or archived for a given insight + action, a new one can be re-recorded. This allows iteration cycles without blocking re-recommendation after action is taken. ✅

**`replaceRecommendation()` — `updatedAt` derivation:**  
`next.appliedAt ?? next.dismissedAt ?? next.archivedAt ?? next.createdAt` — four-way chain covering all terminal timestamp fields. ✅

**`validateInsightSet()` — 6-layer validation chain returning data:**

```ts
private async validateInsightSet(insightSetId, command):
  Promise<Result<{ performanceId, variantSetId, contentId }, ...>> {
  // 1. InsightSet exists
  // 2. InsightSet belongs to business
  // 3. Performance exists (via insightSet.performanceId)
  // 4. Performance belongs to business
  // 5. VariantSet exists (via insightSet.variantSetId)
  // 6. VariantSet belongs to business
  // 7. Content exists (via insightSet.contentId)
  // 8. Content belongs to business
  // 9. Plan exists (via variantSet.planId)
  // 10. Plan belongs to business
  // 11. Calendar exists (via plan.calendarId)
  // 12. Calendar belongs to business

  return success({ performanceId, variantSetId, contentId });
}
```

Returns three IDs — all required to construct the `ContentRecommendationSet` without secondary lookups. Traversal: insightSet → performance + variantSet → content → plan → calendar. ✅

**`generateContentRecommendation()` insight gate:**

```ts
const insight = insightSet.getInsight(command.insightId);
if (!insight || insight.status !== "open") {
  return failure({ code: "ValidationFailed",
    message: `Open content insight ${command.insightId} was not found.` });
}
```

Only `"open"` insights can generate recommendations — resolved, archived insights are rejected at the application layer before reaching the domain. ✅

**`createContentRecommendationRecordedEvent()` — fallback ID resolution:**

```ts
const recommendationId = command.recommendationId ??
  recommendationSet.listRecommendations().at(-1)?.recommendationId;
```

When `command.recommendationId` is optional (auto-generated), falls back to the most-recently appended recommendation. Consistent with the overall pattern of post-mutation lookup. ✅

**`createBaseEvent()` pattern:**  
`aggregateType: "ContentRecommendationSet" as const`, `version: 1 as const`. Consistent with all prior services. ✅
