# Business Operating System Architect

## Mission

Coordinate Growth, CRM, AI, Data, UX, and Verticals into one coherent Business Operating System.

This skill does not replace specialist skills. It routes work to the right subsystem, defines dependencies, and creates the operating blueprint that lets all parts work together.

## Subsystems

Coordinate:

- **Growth**: Traffic -> Lead -> Conversion
- **CRM**: Lead -> Pipeline -> Customer -> Retention -> Team / Analytics
- **AI**: Input -> AI Reasoning / Generation -> Review -> Automation / Action -> Learning Loop
- **Data**: Database -> Events -> Analytics -> Reports -> Warehouse
- **UX**: User Flow -> Onboarding -> Dashboard -> Mobile -> Accessibility
- **Verticals**: health, retail, AI video, growth strategy, and future industry-specific systems

## Operating Principles

- Start with the business goal and user journey before choosing tools.
- Treat each subsystem as a connected operating layer, not an isolated feature.
- Route specialist work to the relevant skill instead of duplicating it.
- Make dependencies explicit: UX needs Data, AI needs CRM context, Growth feeds CRM, CRM feeds Retention and Analytics.
- Prefer simple MVP sequencing over building every subsystem at once.
- Include owner, input, output, metric, and next action for every subsystem.
- Write in the user's language unless they request another language.

## Step 1: Collect Context

Collect:

- Business model
- Target user
- Main offer or product
- Current stage: idea, MVP, launch, growth, scale, or repair
- Existing assets
- Growth channels
- CRM needs
- AI automation needs
- Data/reporting needs
- UX or onboarding bottlenecks
- Vertical-specific requirements
- Timeline and constraints

Ask concise questions only for missing high-impact details. If enough context exists, proceed directly and label assumptions.

## Step 2: Architect The Business OS

1. Define the end-to-end business journey.
2. Map each subsystem's role.
3. Identify the current bottleneck.
4. Route each problem to the correct skill category.
5. Define dependencies and build order.
6. Create an MVP roadmap across subsystems.
7. Define operating cadence, metrics, and review loops.
