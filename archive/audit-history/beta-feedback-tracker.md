# Beta Feedback Tracker

## Purpose

Capture beta feedback in a structured way so product decisions are based on outcome blockers, not scattered feature requests.

## Feedback Rules

- Record feedback within 24 hours.
- Tie every feedback item to a user, route, journey step, and outcome impact.
- Separate confusion, friction, bugs, and feature requests.
- Prioritize blockers that prevent first win, retention, value realization, expansion, or referral.

## Severity

| Severity | Definition | Response Time |
| --- | --- | --- |
| Critical | Blocks signup, login, interview, dashboard, lead capture, or data access | Same day |
| Major | Blocks a beta outcome for one or more users | 24 hours |
| Minor | Causes confusion but workaround exists | 3 days |
| Suggestion | Nice-to-have improvement | Backlog |

## Type Taxonomy

| Type | Use When |
| --- | --- |
| Confusion | User does not understand what to do or why it matters |
| Friction | User understands the action but it takes too much effort |
| Bug | Intended behavior fails |
| Missing Guidance | AI COO or dashboard does not guide next action clearly |
| Feature Request | User asks for new capability |
| Outcome Blocker | User cannot reach first content, lead, customer, sale, expansion, or referral |

## Outcome Impact

| Impact | Definition |
| --- | --- |
| Activation | Blocks interview, Brand DNA, first content, or activation score |
| Retention | Makes user less likely to return |
| Value | Blocks first lead, customer, sale, or first win |
| Expansion | Blocks scaling a proven result |
| Referral | Blocks invite, testimonial, review, referral, or advocacy |
| AI COO | Makes recommendation feel wrong, irrelevant, or unsafe |
| Dashboard | User cannot understand next action quickly |

## Daily Triage

| Question | Action |
| --- | --- |
| Does this block a success-path step? | Assign Critical or Major |
| Does this affect more than one beta user? | Escalate priority |
| Does this create wrong AI COO guidance? | Add to AI COO validation queue |
| Does this prove the product cannot work without human help? | Add to launch learning log |
| Is this only a preference? | Backlog unless repeated |

## Closeout Requirements

A feedback item can be closed only when one of these is true:

1. Fixed and verified by the reporting user.
2. Accepted as known limitation with documented workaround.
3. Rejected with product rationale.
4. Merged into a higher-level issue or launch learning.
