## CP1 — G0 unified generation gateway (blueprint: 已完成, PR #147 / `fef84f2`)

**Requirement:** all generate services route through the `modules/ai` router (`getRouterForTenant().generate()`); a unified generation context injects Brand DNA (+version) + mode (Retail/Recruitment) + platform characteristics + business-pack slice; each module's template copy is demoted to an **explicit, user-visible degrade path** and no longer masquerades as generation; LLM must go through the router — no service-to-provider direct calls.

**Every property is real and traced in source:**

- **Single seam, correct order** — `runGeneration` (`gateway.ts:17-59`): `await enforceQuota(tenantId)` → `await getRouterForTenant(tenantId)` → `router.generate({ systemPrompt, userMessage, temperature, maxTokens }, taskCategory)` → `await logAIUsage(...)`. The gateway test asserts the literal call order `['quota','router','generate','usage']`. ✓
- **Context assembly is module-neutral** — `buildGenerationContext` (`context.ts:64-80`) resolves `getBrandContext` + `getBrandDnaVersion` in parallel and packs `{ brandContext, brandDnaVersion, mode, platform: PLATFORM_CHARACTERISTICS[...], businessPack }`. `composeGenerationSystemPrompt` (`context.ts:83-102`) reuses the existing `buildBrandContextPrompt` (does **not** reimplement Brand DNA), then appends `【品牌 DNA 版本】`, `【生成模式】` (Retail/Recruitment direction), `【平台写作风格】`, and the optional `【事业包上下文】`. ✓
- **Explicit, honest degradation** — the catch block (`gateway.ts:50-58`) returns `{ status:'degraded', source:'template_fallback', value: fallback, userVisibleLabel: GENERATION_DEGRADE_LABEL, reason }`. `GENERATION_DEGRADE_LABEL = 'AI 暂时不可用，这是基础版本'` (`types.ts:44`). The success branch returns `source:'ai'`. The two are a discriminated union (`GenerationOutcome<T>`, `types.ts:46-60`), so a consumer cannot read a template value as AI output by accident. The gateway test drives a rejected `router.generate` and asserts the labelled degraded outcome **and** that `logAIUsage` is **not** called on failure. ✓
- **Architecture rule upheld** — grep for `new OpenAI|new Anthropic|GoogleGenerativeAI` across the audited modules returns nothing; the only generation entry point is the router. ✓

**Result: CP1 PASS.**

| **C-1** | **Condition (test coverage)** | CP2 | **The F-15 guardrails' rejection branches are not directly unit-tested.** `parseGeneratedPostJson` (`contentPostGeneration.ts`) throws on missing/empty required fields, `body.length < 80`, non-JSON, and non-string-array `hashtags` — this is what actually converts bad model output into the labelled fallback. No test drives any of those throw paths: grep for the four error strings across `*.test.ts` returns nothing; the service test only exercises the happy path (valid JSON) and the degraded path (`runGeneration` mocked to return `template_fallback`, which never calls `parse`). So the G1 row's "F-15 三缺陷护栏单测覆盖" is accurate for the *prompt-prevention* side (human labels, asserted) and the happy path, but the *detection* side is unverified. The code exists and type-checks; the gap is coverage, not runtime behavior. **Clear by** adding a focused unit test on `parseGeneratedPostJson` asserting each of the four throws (and that a fenced-JSON body still parses). Non-blocking for W1, but it is the one place a stated blueprint claim outruns its evidence. |
| A-1 | Advisory (observability — G5 scope) | CP1 | **The gateway degrade path is silent to observability.** `gateway.ts`'s catch returns the labelled fallback with no `Sentry.captureException`. The blueprint explicitly assigns provider-error Sentry reporting to **G5 (未开始)** ("以后这里必须有心跳"), so this is a known pending gap, not a regression — flagged so it is not lost between waves. |
| A-2 | Advisory (UI surfacing — G5 scope) | CP2 | **`degradedLabel` / `generatedByAi` reach the API payload but no client renders them.** The route returns them in `{ data: post }`, but grep finds no component consuming either. Non-blocking; noted so the "user-visible" promise is closed literally when G5 lands. |
| A-3 | Advisory (correctness wrinkle, low severity) | CP1 | **A `logAIUsage` failure masks a successful generation as a degraded template.** In `runGeneration`, `logAIUsage` is awaited **inside** the try before the success return; if the tracker throws after a real, billed generation, the catch discards the genuine AI text and returns the fallback labelled "AI 暂时不可用." Low probability, but it both wastes the provider call and mislabels real output. Recommend logging usage outside the success/fallback decision (e.g. catch-and-log) so tracker failures never discard generated content. |

## Verdict

**PASS WITH CONDITION.**

Wave 1 of OS 3.9 is real and it is honest. **G0** is a genuine single-seam generation gateway with an explicit, discriminated degrade contract — template output can no longer masquerade as AI, and the label "AI 暂时不可用，这是基础版本" is produced at the source. **G1** routes the content-engine post body through that gateway on the live `/api/v1/content-engine/generate` path, persists structured `title/hook/body/cta/hashtags`, and sets `generatedByAi` truthfully from the outcome source. **O1** is a typed, zod-validated, versioned JSON pack in which every price row and the weight-loss numeric framework are classed `private`, and whose `getBusinessPackSlice({track})` emits a track-scoped, substitution-sanitized public context that I verified — by reading the asset and by the tests — carries zero brand names, zero prices, and zero weight numbers. The architecture rule holds, tenant scoping is correct, and content-engine is the only consumer, so the `未开始` waves (G4/G5/G2/O2–O5/G3/G6/M1) are honestly unstarted.

The work was exercised, not asserted: PRs #147/#148/#149 each went green on all six CI checks including E2E, and the `src` subtree at HEAD is byte-identical to the CI-green commit, one docs line apart. Local type-check, lint (0 errors), 680 tests, build, boundaries ("in sync"), and i18n (1399 × 3, zero missing) are all green, with zero `prisma`/`env`/`packages` diff.

It is not a clean PASS for exactly one reason, and it is a test-coverage reason rather than a runtime defect: the G1 row claims "F-15 三缺陷护栏单测覆盖," but the parser's rejection branches — the guards that actually convert a thin or malformed model response into the labelled fallback — have no direct negative-path test (C-1). The guard code exists, type-checks, and runs on the happy path; only its failure branches are unverified. Advisories A-1 (Sentry on degrade) and A-2 (render the degrade label) are by-design gaps explicitly owned by the pending G5, and A-3 (usage-logging failure masking real output) is a low-severity wrinkle worth tightening.

Ship-blocking issues: **none.** This audit clears the OS 3.9 W1 foundation; C-1 should be closed before the W2 compliance-batch gate (G4/G5) leans on the same F-15 guards.
